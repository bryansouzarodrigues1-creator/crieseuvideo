# User-requested Gemini ark scene

The user requested a new twenty-second story generated by Gemini: Noah's ark in a tsunami, sunlight returning, and animals outside singing. The production script sends that brief through the existing Gemini Code 3D provider. It does not substitute a previous ark demo or hand-author the scene, animal rigs, wave motion or melody.

Only execution support is authored here: the Code 3D duration ceiling now admits twenty-second clips, and an optional bounded PCM response can be extracted from the same opaque iframe. The fixed construction recipe keeps its previous twelve-second clip ceiling. Authentication, provider configuration, CSP and opaque-origin isolation remain unchanged.

`getSoundtrack()` is optional. Its generated code runs only inside the sandbox, never in Node or the app origin. The bridge validates the sample rate, one or two Float32 channels, exact scene duration, finite samples and amplitude bounds. The request/render scripts preserve the original answer, source hash, direction and actual provider call count. The renderer verifies that hash before exporting video and PCM; it does not edit animation or sound code. PCM-to-WAV conversion and final audio/video muxing are format operations only.

The dedicated workflow makes one actual request on this feature branch's PR-open event, after offline checks. If Gemini's program fails or needs visual correction, retain that result and request a Gemini revision rather than silently hand-editing its creative code. Runtime success is separate from visual inspection of the exported scene.

The first request returned a complete twenty-second program with four shots and its own PCM synthesis. Validation rejected its `medium` camera label, which was reasonable but absent from the schema and prompt's explicit enum. The engine now accepts that label and lists the supported values. The exact original answer and failed-request provenance are retained in `scripts/fixtures/ark-gemini.*`; later workflow runs only re-validate and render those bytes, with no second provider request or manual animation/audio change.

# Low/high thinking comparison

The user authorized a controlled comparison after the poor ark render. Generate the same short elephant/deck action with the same Gemini 3.6 Flash model, prompt, aspect ratio and generation configuration. The only request-body difference is `thinkingConfig.thinkingLevel`. Both normalized request hashes must match after removing that field. Exactly one request per level, with no retries or creative code repairs.

The native scene contract starts at eight seconds. Both requests therefore ask for the action to finish in the first five seconds and hold the result from five to eight. Render the original eight-second programs identically and crop the same first five seconds for the comparison. This avoids changing the app's duration contract for a study. Do not speed up or retime either scene.

Keep the original responses, timing, usage metadata and finish reason. Provider acceptance and explicit isolated import are separate outcomes. A valid direction plus syntax can be imported with mechanical score-data injection if needed; this does not change generated geometry, action, camera or poses, and does not weaken the production provider gate. Invalid or failed arms remain failures and are not manually repaired or replaced with a demo.

Inspect the two renders for complete elephant anatomy, visibility, feet/ground contact, coherent exit through the doorway, movement and final pose. Syntax, replay and export success alone are insufficient. Compare equal timestamps and report remaining defects. There is one stochastic sample per level with no fixed seed; conclusions describe this pair, not a general benchmark or proof that more reasoning always improves animation. Request latency is descriptive, with a fixed low-then-high order.

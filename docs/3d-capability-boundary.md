# 3D capability boundary: observed Everest failure

The reported ordinary result shows a presenter and a board for the sentence
“Ele conseguiu escalar o monte Everest mas...”. This is not a climbing animation.
`buildFallbackPlan` has no climbing action. `Toon3D.build` deliberately creates
the legacy presenter/board composition when a scene has neither story nor
staging. Gemini currently directs a fixed catalogue; it cannot add an unimplemented
action or create arbitrary rigs and environments through that JSON contract.

The isolated laboratory now blocks such presentation-only scenes in Toon 3D,
including local rehearsal, direction, saved-project resume, imports, settings
changes and export controls. The server independently rejects unavailable scenes
before asking the provider. Explicit Motion 2D illustration remains available.
The main editor and its legacy renderer are preserved.

This change prevents the specific silent substitution. It adds no climbing rig,
terrain, new assets or new animation. Passing technical tests is not a visual
quality acceptance. A supported reaction does not establish that every event in
the source was demonstrated; the UI no longer describes the count as proof of
complete staging. The availability guard detects presentation fallbacks only,
not all semantic mismatches.

The next substantive animation milestone requires a reusable way to author
physical actions beyond the current catalogue, rigged characters/assets, scene
construction and acceptance on previously unseen scripts through the ordinary
generator. A one-off hand-authored scene is not sufficient evidence. No paid
provider generation is part of this patch.
